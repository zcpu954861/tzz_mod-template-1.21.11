# 测试 7.6 WebAdmin 对象生命周期选择基础验收

## 新世界前置条件

- 使用新世界或确认测试世界中目标方块位置当前没有已登记的 `virtual_block_device`。
- WebAdmin 已启用并可登录，测试账号角色为 EDITOR 或 OWNER。
- 至少 1 名目标玩家在线，目标玩家客户端已加载本 mod。

## 数据准备

- 准备一个普通方块，例如石头、木板、箱子、门或按钮。
- 准备一个有效 channel，例如 `test.vbd.selection`。
- 若要测试冲突，在第一次创建成功后再次选择同一方块。
- 第二阶段删除 / 新建测试需要一个已存在的 VBD 和一个可删除的临时 SignalListener；不要使用生产关键 channel 或关键 listener。

## 本地验证命令

在仓库根目录执行：

```powershell
.\gradlew.bat clean build
.\gradlew.bat stabilizationGuardTest --rerun-tasks
git diff --check
```

## 浏览器验收步骤

### 第一阶段：选择创建 VBD

1. 打开 WebAdmin 并进入 `#/virtual-block-devices`。
2. 点击“新建虚拟方块设备”。
3. 目标玩家字段应显示暗色在线玩家下拉，可过滤并选择在线玩家，同时仍允许手动输入玩家名。
4. Channel 字段应显示暗色已有频道下拉，可过滤并选择已有 channel，同时仍允许手动输入新 channel；新 channel 不应自动创建消费者。
5. 输入目标玩家名和 channel，可选填写显示名、备注、图标。
6. 点击“开始选择”。
7. 目标玩家客户端应显示选择模式 UI：
   - “选择虚拟方块设备目标”
   - “右键方块确认”
   - “ESC 取消”
   - 小窗口、不同 GUI scale 下文字不溢出屏幕，不遮挡准星或核心视野。
8. 光标应被 Minecraft 捕获，OS 光标不应停留在游戏窗口上；移动鼠标应转动视角。
9. 玩家移动、跳跃、潜行和转动视角应保持可用。
10. 玩家手持任意物品右键目标方块，应该完成选择。
11. 选择过程中不应打开箱子、门、按钮、工作台、手机、背包或其它 GUI。
12. 创建成功后目标玩家只收到一次绿色私聊提示“选择成功”。
13. 客户端自动退出选择模式。
14. WebAdmin 自动跳转到新设备详情，modal 不应留下可反复点击的“查看详情”按钮。
15. 从新设备详情点击返回，应回到 `#/virtual-block-devices` 或发起创建的来源页。
16. 再次对同一方块发起选择时，应显示冲突，不覆盖已有 VBD。
17. 重新发起选择后按 ESC，应只收到一次取消提示，且不创建设备。

### 第二阶段：VBD 删除 / 解绑

1. 在 `#/virtual-block-devices` 或 VBD 详情页选择一个测试 VBD。
2. 点击“解绑”或“删除 / 解绑”。
3. Modal 必须是 7.5 fixed dangerous confirm modal，显示设备 ID、世界、坐标、方块 ID、channel 和“不会破坏世界方块”的说明。
4. 未勾选确认或未输入设备 ID / 显示名称时，提交应失败并保持 modal 打开。
5. 正确确认后提交，Network 应出现 `POST /api/webadmin/virtual-block-devices/{deviceId}/delete` 并携带 `X-TZZ-WebAdmin-CSRF`。
6. 删除成功后 VBD 列表刷新，当前详情页应返回 `#/virtual-block-devices`。
7. 进入游戏确认原世界方块仍存在，未被 setblock / break。
8. 使用第一阶段选择模式重新选择同一方块，应能再次创建新的 VBD。

### 第二阶段：SignalListener 新建 / 删除

1. 打开 `#/listeners`。
2. 点击“新建监听器”。
3. Channel 字段必须是暗色 combobox，可选择已有 channel，也可手动输入新 channel；新 channel 不应自动创建 receiver/device/action。
4. 输入 listener 名称、channel、enabled、cooldownTicks 后保存。
5. Network 应出现 `POST /api/webadmin/signal-listeners` 并携带 `X-TZZ-WebAdmin-CSRF`。
6. 创建成功后自动进入 `#/listeners/<id>?returnTo=%23%2Flisteners`。
7. 新建 listener 的 actions 应为空，并显示后续动作编辑阶段再配置。
8. 在 listener 详情或列表点击删除。
9. 删除 modal 必须显示 listener 名称、ID、channel、action count，并明确不会删除 channel、receiver、device 或历史记录。
10. 未确认时提交失败并保持 modal 打开；正确确认后 Network 应出现 `POST /api/webadmin/signal-listeners/{listenerId}/delete`。
11. 删除成功后返回 `#/listeners`，列表不再显示该 listener。

## 失败判定

- 只有空手右键才选择。
- 右键同时触发了原方块交互或手持物品使用。
- 选择模式中可以打开背包或其它 screen。
- Minecraft 小窗口或高/低 GUI scale 下选择 UI 文字越界、重叠或遮挡核心操作区域。
- 选择 UI 出现后 OS 光标仍可见，鼠标移动不能转动视角，或点击窗口后仍无法锁定鼠标。
- 成功或取消聊天提示重复出现。
- completed 后又显示 cancelled。
- 创建成功后详情页返回到了 `#/devices` 而不是虚拟方块设备来源页。
- completed 后 modal 留下可重复点击的详情跳转按钮。
- 成功提示广播给了其它玩家。
- 同一位置已有 VBD 时被覆盖。
- WebAdmin 白屏、整页 reload、关闭无关 modal、重置筛选或分页。
- 创建过程中绕过 CSRF / same-origin / WebAdminWriteResult / audit。
- VBD 删除破坏了世界方块，或误删了其它类型 signal device。
- SignalListener 新建同时创建了 action、matcher、itemSubmit 或 ConditionEngine 配置。
- SignalListener 删除误删了 channel、receiver、device 或历史记录。
- 删除失败时 modal 被关闭，导致用户看不到错误。

## Console / Network 检查

- WebAdmin Network 中应出现 `POST /api/webadmin/selection/start`。
- 取消时应出现 `POST /api/webadmin/selection/cancel`。
- VBD 删除应出现 `POST /api/webadmin/virtual-block-devices/{deviceId}/delete`。
- SignalListener 新建应出现 `POST /api/webadmin/signal-listeners`。
- SignalListener 删除应出现 `POST /api/webadmin/signal-listeners/{listenerId}/delete`。
- 请求应携带 `X-TZZ-WebAdmin-CSRF`。
- realtime 应出现 selection、device、virtual block、signal listener、config 或 audit 相关事件，WebAdmin 不应使用整页 reload。
- Browser console 不应出现未捕获异常。
