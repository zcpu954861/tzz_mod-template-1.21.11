# 7.9 WebAdmin 虚拟方块设备原生触发配置 P1 验收

## 范围

本轮只验收 `virtual_block_device` 原生触发配置的数据驱动只读摘要、BlockState 当前方块属性读取基础，以及统一设备配置 modal 内的原生触发配置骨架。

P1 不验收写入，不应出现 native trigger 保存按钮或持久化写 API。

## 前置条件

1. 使用新世界或已完成 7.8 验收的测试世界。
2. WebAdmin 已登录 EDITOR / OWNER 或 VIEWER 账号。
3. 至少存在一个 `virtual_block_device`。
4. 建议准备一个绑定到带 BlockState 属性方块的 VBD，例如 lever / button / door。

## 浏览器验收步骤

Guard marker：
- 只显示 active 触发摘要
- 红石摘要
- BlockState 属性读取
- 容器 open / close / change 摘要
- 不出现 itemSubmit / consume / ConditionEngine / 路径图
- Console / Network
- 无手动触发方式选择器
- active trigger data-driven summary
- native trigger compact cards
- readonly native trigger detail modal
- matcher toggle preserves modal scroll
- no configured trigger empty state
- channel catalog 与 combobox 来源一致

1. 打开 `#/virtual-block-devices`。
2. 进入任意 VBD 详情页。
3. 确认详情页右侧 detail / secondary column 出现“原生触发配置”区域，不挤在左侧主内容流里。
4. 确认页面不出现“触发方式选择器 / 显示过滤 / 当前显示”这类手动 selector 文案或按钮。
5. 根据当前 VBD 实际配置确认只显示已启用 / 已配置的触发紧凑小卡片：
   - 只配置红石时只显示红石小卡片。
   - 只配置 BlockState 条件时只显示 BlockState 小卡片。
   - 配置红石 + 容器变化时只显示这两个小卡片。
   - 没有原生触发配置时显示“尚未启用原生触发方式。完整编辑将在 7.9 P2 支持。”。
6. 确认未配置的触发方式卡片不会显示；已配置触发也不在详情页直接展开长篇字段。
7. 点击任一原生触发小卡片，确认打开只读详情 modal：
   - modal 内显示完整字段。
   - 没有保存按钮。
   - 不获取 edit lock。
   - 关闭后不影响详情页滚动位置。
8. BlockState 只读详情中确认：
   - 当前方块属性来自绑定方块实际属性。
   - 属性值下拉 / 预览只展示该属性实际支持值。
   - 不显示泛用属性大列表。
9. 右键交互 active 时确认只在小卡片中显示简要摘要，点击详情后显示：
   - interactionEnabled
   - interactChannel
   - interactionCooldownTicks
   - 最近交互玩家 / 结果
   - 7.8 interaction item matcher 作为右键交互之后的条件层关联摘要和编辑入口。
   - 如果 matcher 已配置但右键交互未启用，应在右键交互摘要内提示“已配置交互物品匹配，但右键交互触发尚未启用”。
10. 容器打开、容器关闭、容器内容变化 active 时确认只显示对应小卡片，完整字段只在只读详情中查看。
11. 打开“编辑设备配置”modal。
12. 确认 modal 内有“原生触发配置”section。
13. 确认该 section 明确是 P1 只读骨架，不提供保存 native trigger 的按钮。
14. 确认 7.8 交互物品匹配编辑能力仍可从原生触发配置 / 右键交互上下文进入。
15. 打开交互物品匹配编辑：
   - “要求交互物品匹配”未启用时，只显示总开关和说明，不展开 item id / count / damage / 自定义名称 / Lore 细项。
   - 启用后显示物品 ID、数量规则、source / 原版交互策略。
   - 数量规则为“不检查数量”时，数量输入收起。
   - damage / 自定义名称 / Lore 的值输入只在对应开关启用后显示。
   - 在统一设备配置 modal 中切换这些开关时，modal 滚动位置不应跳回顶部或跳到底部。
   - 关闭开关不应误清其它 matcher 字段；保存失败时 modal 保持打开。
16. 使用 WebAdmin 创建 VBD 时输入一个新 channel，确认 Signal 页面能看到后，设备配置、VBD 创建、SignalListener、ActionRelay signal action 等 channel combobox 也能看到该 channel。

## 禁止项检查

页面中不应出现：

- itemSubmit 编辑器。
- consume 编辑器。
- inventory / equipment / armor 编辑器。
- ConditionEngine。
- 成功 / 失败路径图。
- graph / mind-map / Scratch-like 编辑器。
- raw JSON textarea。
- 容器内容变化物品模板 GUI。
- native trigger POST / PATCH / DELETE 请求。

## Network / Console 检查

1. 打开 DevTools Network。
2. 打开详情页和统一设备配置 modal。
3. 确认不会因为原生触发摘要发送 POST / PATCH / DELETE。
4. 允许出现 GET：
   - `/api/devices/<deviceId>`
   - `/api/webadmin/virtual-block-devices/<deviceId>/native-triggers`
5. Console 不应出现新的 JavaScript error。

## 布局检查

1. 大屏下原生触发摘要应位于右侧 detail / secondary column，用来填充右侧空白并平衡左右高度。
2. 摘要卡应为紧凑小卡片，不应无意义横跨整行；无配置时空状态应保持紧凑。
3. 中小屏下不应重叠、横向撑爆或遮挡按钮。
4. 统一设备配置 modal 内 section 应在内部滚动区域内显示，不应撑出 fixed modal。

## 失败判定

任一情况视为失败：

- VBD 详情页没有“原生触发配置”区域。
- 出现手动触发方式 selector / filter。
- 显示未配置的触发摘要卡片。
- 已配置原生触发在详情页直接展开长篇完整字段，而不是先显示紧凑小卡片。
- 点击原生触发小卡片不能打开只读详情 modal，或只读详情出现保存按钮 / edit lock。
- 在统一设备配置 modal 中切换 matcher 开关后滚动位置跳回顶部或底部。
- 无原生触发配置时没有显示空状态。
- Signal 页面可见的 channel 在 channel combobox 中不可见。
- BlockState 属性不是来自当前绑定方块实际属性。
- 目标值不是来自该属性实际支持值。
- P1 出现 native trigger 保存按钮或写 API。
- 出现 itemSubmit / consume / ConditionEngine / 路径图 / raw JSON。
- 打开统一设备配置 modal 后找不到原生触发配置 section。
- 7.8 interaction item matcher 被显示为独立原生触发源、独立长期详情卡片，或脱离右键交互条件层单独占位。
- Console 出现新错误。
