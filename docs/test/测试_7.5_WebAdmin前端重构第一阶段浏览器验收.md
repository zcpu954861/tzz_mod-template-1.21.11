# 7.5 WebAdmin 前端重构第一阶段浏览器验收

本文档用于验证 7.5 WebAdmin UI Refactor Foundation / Step 1 当前落地范围：登录页、新 App Shell、Dashboard、SignalBridge、接收器页面、整卡/整行跳转、静默刷新和响应式布局。

## 命令来源

以下命令来自当前代码：

- 根命令：`src/main/java/com/zcpu/tzzmod/command/TzzRootCommand.java`
- WebAdmin 用户命令：`src/main/java/com/zcpu/tzzmod/webadmin/WebAdminCommand.java`
- Signal 命令：`src/main/java/com/zcpu/tzzmod/signal/SignalCommand.java`
- 设备绑定命令：`src/main/java/com/zcpu/tzzmod/signal/device/SignalDeviceCommand.java`
- 接收器命令：`src/main/java/com/zcpu/tzzmod/signal/device/SignalReceiverCommand.java`
- 接收器方块 ID：`src/main/java/com/zcpu/tzzmod/ModBlock/ModBlocks.java`

当前 Signal channel 校验来自 `SignalChannel.java`：只允许小写字母、数字、`_`、`.`、`:`、`-`，长度 1-128。`webadmin/basic-valid` 里的 `/` 当前不是合法 channel；不要把它作为成功通道使用。

## 新世界前置条件

1. 使用有权限的 OP/创造模式玩家进入新世界。
2. 确认 WebAdmin 已启用并运行：

```mcfunction
/tzz webadmin status
```

3. 创建测试 WebAdmin 用户，记录命令返回的初始密码：

```mcfunction
/tzz webadmin user create ui75 OWNER
```

可用角色为 `VIEWER`、`TESTER`、`EDITOR`、`OWNER`。

## 创建接收器测试数据

站在要放置接收器的位置，依次执行：

```mcfunction
/setblock ~ ~ ~ tzz_mod:signal_receiver
/tzz signal device bind ~ ~ ~ webadmin.75.alpha
/tzz signal device name ~ ~ ~ UI75 接收器 Alpha
/tzz signal receiver info ~ ~ ~
/tzz signal receiver pulse ~ ~ ~ 20
/tzz signal receiver info ~ ~ ~
```

`/tzz signal receiver info <pos>` 第一次应显示默认脉冲时长 5 GT / 5 tick；`/tzz signal receiver pulse <pos> <ticks>` 来自当前 Brigadier 注册，格式为 `/tzz signal receiver pulse <pos:blockPos> <ticks:int[1..72000]>`，示例把 pulseTicks 改为 20。

手动触发接收器红石脉冲：

```mcfunction
/tzz signal receiver trigger ~ ~ ~
```

也可以通过 channel 发射信号触发：

```mcfunction
/tzz signal emit webadmin.75.alpha
```

## SignalBridge 测试 channel

创建/触发几个合法 channel：

```mcfunction
/tzz signal emit webadmin.75.alpha
/tzz signal emit webadmin.ext.interact
/tzz signal emit webadmin:basic-valid
```

查看 channel 列表和详情：

```mcfunction
/tzz signal channels
/tzz signal channel info webadmin.75.alpha
```

负向验证：当前 `/` 不被 `SignalChannel` 允许，下面命令预期失败。它用于确认不要把旧提示里的 slash channel 当作有效成功数据：

```mcfunction
/tzz signal emit webadmin/basic-valid
```

## 详情页 7.5 返修验收

本节用于验证 7.5 详情子页面返修，不进入 7.6，不要求新增后端 API。Figma 参考图只作为信息架构和视觉密度参考，不要求像素照搬。

浏览器直接打开以下路由，`<channel>` / `<id>` 使用当前世界里真实存在的数据；没有数据时可先用上文 signal / receiver 命令创建基础数据：

- `http://127.0.0.1:18080/app#/signals/<channel>`
- `http://127.0.0.1:18080/app#/listeners/<id>`
- `http://127.0.0.1:18080/app#/signal-listeners/<id>`
- `http://127.0.0.1:18080/app#/devices/<id>`
- `http://127.0.0.1:18080/app#/actions/<id>`
- `http://127.0.0.1:18080/app#/regions/<id>`

验收标准：

1. 每个详情页顶部应是 7.5 detail Header：对象图标、标题、ID / type / status badge、复制或右侧操作区；不应只是单独返回按钮 + 标题。
2. 每个详情页 Header 下方应有 Tabs；频道页包含“基本信息 / 监听器列表 / 最近事件 / 触发统计 / 递归检查”，监听器页包含“基本信息 / 动作列表 / 最近事件 / 触发统计 / 递归检查”。
3. 详情页主结构应为 first row：基本信息 + 状态统计，second row：列表 / 最近事件 / 分布 / 右侧信息栈；不应出现顶部一整排大 metric cards。
4. 频道详情应显示基本信息、状态统计和消费者关系，并在 second row 显示监听器列表、最近事件、动作类型分布；“逻辑链”不能作为主结构大块替代这些内容。
5. 监听器详情应显示基本信息、状态统计、动作列表、冷却状态和操作工具；动作列表当前只读，不应启用新增、删除或 reorder action。
6. 设备详情应保留“编辑设备配置”入口，并在一个 7.5 fixed modal 中统一显示显示信息、基础配置和类型专属扩展配置；不应拆回两个旧编辑区块。
7. 动作详情和区域详情应按同一 detail shell 派生：Header、Tabs、基本信息、状态统计、second row 和右侧信息栈，不应回到旧式纵向堆叠或 raw config 块。
8. 每个详情页应存在默认折叠的“完整详情”卡片；点击“显示全部详情”后展示低频字段 / debug / runtime / fingerprint / configSummary 等额外字段，再点击“收起详情”恢复紧凑状态。
9. “完整详情”展开后内容应在卡片内部滚动或分组显示，不应把整页撑成超长旧页面；静默刷新不应重置展开 / 收起状态。
10. 打开 channel metadata、listener basic config、统一设备配置 modal 后，页面主体不应重排或闪烁；modal 应有半透明遮罩、backdrop blur、淡入淡出、固定 header/footer 和 body 内部滚动。
11. 保存失败时 modal 应保持打开并显示错误；取消或关闭应释放 edit lock。Network 面板中不应出现无后端支持按钮发出的 POST / PATCH / DELETE。
12. 未支持的导出、删除、创建消费者、动作链编辑、测试执行、区域定位等按钮保持 disabled / unavailable。
13. Console 不应出现 `ReferenceError`、白屏、永久 loading 或路由渲染失败。

## Dashboard 验收

1. 6 张概览卡主图标应为 2D 平面、纯色、简单几何线条 SVG，形状明显更新，不应只是旧图标染色。
2. 指标行小图标应为同一纯色几何 SVG 图标族，有颜色、有语义，且不压文字。
3. 设备、Doctor、Signal、区域、动作、用户 6 张主卡图标形状应各不相同。
4. 点击整张概览卡应跳转到对应页面，不应只靠“查看详情”文字。
5. 使用键盘 Tab 聚焦卡片后，Enter / Space 应触发同样跳转。
6. Hover 卡片应有边框或阴影反馈。

## SignalBridge 验收

1. 顶部统计卡图标应为纯色几何 SVG 图标，不应只是旧图标染色。
2. 消费者摘要图标应为纯色几何 SVG 图标，有颜色、有语义。
3. 消费者摘要顺序固定为 listener / receiver / relay / region。
4. listener / receiver / relay / region 的消费者摘要图标语义应正确。
5. 点击频道表格任意一行非按钮区域，应进入 `#/signals/<encoded-channel>` 频道详情。
6. “详情”按钮应进入同一详情路由。
7. Raw Channel 长文本应 ellipsis，不应执行或破坏页面。
8. `webadmin:basic-valid` 等包含冒号/短横线的合法 channel 应能安全跳转。
9. `webadmin/basic-valid` 当前应作为非法 channel 负向用例，不要求在 SignalBridge 成功显示。

## 几何 SVG 图标专项验收

1. Dashboard 主图标应为参考图风格的 2D 平面、纯色、简单几何线条图标，不存在旧 SVG 图标染色。
2. Dashboard 指标行图标应为同一几何 SVG 图标族，缩小后仍能辨认。
3. SignalBridge 统计卡图标应为纯色几何 SVG 图标。
4. SignalBridge 消费者摘要图标应为纯色几何 SVG 图标，listener / receiver / relay / region 语义正确。
5. Receivers 统计卡、表格行、快速操作相关图标应为纯色几何 SVG 图标。
6. Sidebar / topbar 关键图标应为纯色几何 SVG 图标，包括 logo、Dashboard、SignalBridge、receiver、history、doctor、region、device、action、user、settings、server-online、logout。
7. 图标本体不能带圆形底、方形底、渐变背景图、阴影底板、复杂纹理或卡片底。
8. UI 圆形底、卡片底、hover 和 glow 应由 CSS 提供，不应画进图标本体。
9. 图标不能有位图噪声、脏边、抠图残留或背景残留。
10. Dashboard 主图标应在圆形容器内居中，不偏移、不裁切。
11. Dashboard 指标行图标应居中，不压文字。
12. SignalBridge 消费者摘要图标应居中，数字间距稳定。
13. Sidebar / topbar 图标应垂直居中，不贴边、不裁切。
14. Receivers 统计卡、表格行和 pulse duration 图标应居中，不影响行高。
15. 当前实现应通过统一 inline SVG registry 渲染图标，不应出现 broken image。
16. 页面中不应出现旧图标染色、无色旧图标、emoji、字母或纯字符图标占位。
17. 图标在暗色背景下应清晰，不压文字，不把行高或按钮尺寸撑乱。
18. 表格尺寸下 14-18px 的消费者摘要和接收器行图标仍应可辨认。
19. 图标应继承 CSS 语义色；Dashboard、SignalBridge、Receivers、sidebar/topbar 不应显示成无色或单调灰白。
20. Dashboard 主图标、sidebar 图标、消费者摘要图标和接收器行图标视觉大小应合适，不要过大、过小、偏移或裁切。
21. 本轮参考的 18 张图只用于 Step 1 图标风格，不应扩展其它未落地页面重构。

## 接收器页验收

1. 打开 `#/receivers` 后，页面语义应为 signal -> redstone pulse。
2. 新放置并绑定 `tzz_mod:signal_receiver` 后，不刷新浏览器，页面应在约 5 秒轮询窗口内静默更新。
3. 新建 signal_receiver 后，在未执行 pulse 命令前，表格“脉冲时长”应显示默认 `5 tick`。
4. 执行 `/tzz signal receiver pulse ~ ~ ~ 20` 后，不刷新浏览器，等待 silent refresh，表格“脉冲时长”应更新为 `20 tick`。
5. 旧设备详情页的“脉冲时间”和新接收器列表显示应一致。
6. pulseTicks 详情加载中可以显示“加载中”，加载失败显示 `--`，不应长期显示“未提供”。
7. 静默刷新不得白屏、黑屏、整页 reload、重置滚动、重置筛选、重置分页或关闭 modal。
8. 表格行如果有设备详情路由，应可整行进入设备详情。
9. 右侧筛选栏输入框、下拉框、应用/重置按钮不得重叠。
10. 未实现写操作按钮保持 disabled，不发送 POST / PATCH / DELETE。

## Silent Refresh 验收

1. Receivers 页面约 5 秒静默刷新，不闪屏，不 reload。
2. 静默刷新不重置筛选、分页、滚动或当前输入焦点。
3. 当前可见接收器行的详情缓存应刷新，pulseTicks 应跟随详情数据更新。
4. 切到后台标签页时可暂停或延迟刷新；回到前台后应继续静默刷新。

## 响应式验收

- 3840 x 2160：内容自然扩展，不缩成 1536 小画布。
- 2560 x 1440：主内容宽度合理。

- 1280 x 720：接收器 right rail 可下移。
