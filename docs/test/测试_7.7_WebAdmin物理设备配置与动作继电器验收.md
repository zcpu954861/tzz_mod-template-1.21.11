# 测试 7.7 WebAdmin 物理信号设备配置与动作继电器验收

## 新世界前置条件

- 使用新世界，或确认测试世界中有可替换的 `signal_emitter`、`signal_receiver`、`action_relay` 测试方块。
- WebAdmin 已启用并可登录，测试账号角色为 EDITOR 或 OWNER。
- 至少 1 名玩家在线并拥有放置 / 破坏测试方块的权限。
- 本轮只验证已放置物理方块设备的配置，不通过 WebAdmin 创建或删除物理方块。

## 数据准备

1. 在游戏内放置一个 `signal_emitter`、一个 `signal_receiver` 和一个 `action_relay`。
2. 使用当前命令树确认可见设备：

```text
/tzz signal device list
```

3. 为动作继电器准备测试 channel，例如：

```text
/tzz signal relay bind <x> <y> <z> test.relay.webadmin
/tzz signal relay addAction <x> <y> <z> message WebAdmin relay test
/tzz signal relay listActions <x> <y> <z>
```

4. 如果命令补全显示参数格式与上述示例不同，以当前 TAB 补全为准；不要使用裸 `/tzz signal` 或历史父命令猜测。

## 本地验证命令

在仓库根目录执行：

```powershell
.\gradlew.bat clean build
.\gradlew.bat stabilizationGuardTest --rerun-tasks
git diff --check
```

## 浏览器验收步骤

### 物理设备配置边界

1. 打开 WebAdmin 并进入 `#/devices` 或 `#/block-devices`。
2. 找到 `signal_emitter`、`signal_receiver`、`action_relay` 三类真实方块设备。
3. 三类物理设备都不应出现“删除设备”“解绑设备”或任何会破坏世界方块的按钮。
4. VBD 仍应保留删除 / 解绑入口，且仅作用于 `virtual_block_device`。
5. 打开三类设备详情，确认基础配置编辑仍使用 7.5 fixed modal，不出现 raw JSON textarea。
6. 配置保存应携带 CSRF，失败时 modal 保持打开并显示错误。
7. 即使 Action 列表提示 block entity / chunk 不可编辑，三类物理设备的 displayName、note、iconKey、enabled、channel 基础配置入口仍应可见。

### signal_emitter 语义

1. 打开 `signal_emitter` 详情或配置 modal。
2. 可以编辑当前安全字段，例如 enabled、channel、displayName、note、iconKey。
3. 不应出现删除 / 解绑真实方块设备入口。
4. 不应出现 Action 列表入口。

### signal_receiver 语义

1. 打开 `signal_receiver` 详情或配置 modal。
2. 可以编辑当前安全字段，例如 enabled、channel、pulseTicks、displayName、note、iconKey。
3. 不应出现 Action 列表入口。
4. 不应出现任意输出目标绑定。
5. 不应允许 receiver 执行 command / signal / message / sound action。

### action_relay Action 列表

1. 在信号设备列表行右侧三点更多菜单中，`action_relay` 行应显示“查看 / 编辑 Action 列表”。
2. 非 `action_relay` 行不应显示该入口，或必须明确 disabled 并说明仅 action_relay 支持。
3. 打开 `action_relay` 详情页，应看到 Action 列表卡片和“编辑 Action 列表”按钮。
4. 打开设备配置 modal，modal 内也应有 Action 列表 section / button，不能只能从外部入口进入。
5. `action_relay` 基础配置 modal 中应可编辑 enabled、channel、cooldownTicks、displayName、note、iconKey。
6. 如果 Action 列表不可编辑，提示应区分 world unavailable、chunk unloaded、block entity missing、block entity type mismatch，不应一律显示“区块未加载”。
7. Action 列表 modal 应是 7.5 fixed modal：毛玻璃遮罩、固定 header/footer、body 内部滚动、暗色输入和 combobox。
8. 新增 command action，填写命令文本并保存。
9. command action 应允许保存 `setblock`、`fill`、`clone`、`place`、`function`、`schedule function`、`execute ... run setblock`、`give`、`tp` 等地图控制 / 玩法命令。
10. command action 不应允许保存 `ban`、`ban-ip`、`kick`、`op`、`deop`、`stop`、`whitelist`、`pardon`、`pardon-ip`、`save-off`、`save-on` 等服务器管理高风险命令；失败时 modal 保持打开并显示校验错误。
11. 新增 signal action，channel 字段应是暗色 combobox，既能选择已有 channel，也能手动输入新 channel。
12. 新增 message action，填写消息文本并保存。
13. 新增 sound action，填写 sound id、volume / pitch 等当前底层支持字段并保存；如果底层当前只保存 sound id，则 UI 不应硬造无效字段。
14. 编辑已有 action 后保存，列表顺序和其它 action 字段应保持。
15. 使用上移 / 下移按钮调整 action 顺序，保存后刷新仍保持顺序。
16. 删除单个 action 时应出现危险确认或清晰删除状态，删除失败时 modal 保持打开。
17. 保存成功后列表和详情 silent refresh，不整页 reload，不重置其它筛选 / 分页 / 滚动。

### 多用户 / 冲突

1. 浏览器 A 打开某个 action_relay Action 列表并开始编辑。
2. 浏览器 B 修改同一个 action_relay 的配置或 action list 并保存。
3. 浏览器 A 不应被静默覆盖输入。
4. 浏览器 A 再保存时应提示配置已变化，需要刷新 / 重新打开。
5. 与当前 route 无关的页面不应因为 action list 保存而大范围重拉数据或闪屏。

### 写安全负向检查

1. 使用 VIEWER 或 TESTER 账号打开 action_relay 详情，Action 列表可以查看但保存入口应 disabled，直接伪造 PATCH 也应返回权限失败。
2. 删除或篡改 `X-TZZ-WebAdmin-CSRF` 后提交保存，应返回 CSRF 失败，不写入 action list。
3. 使用非同源 Origin / Referer 伪造保存请求，应返回来源校验失败。
4. 不带 `lockId`、使用过期 `lockId` 或未持有 edit lock 保存，应返回 edit lock 失败。
5. 使用旧的 `expectedFingerprint` 保存，应返回 conflict，并提示刷新 / 重新打开。
6. 以上失败场景都不应关闭 modal，不应发布成功提示，不应改变游戏内 action list。

### 游戏内破坏方块同步

1. 在游戏内破坏测试物理设备方块。
2. WebAdmin 相关设备列表 / 详情应通过 realtime 标记 dirty 并 silent refresh。
3. WebAdmin 不应提供替代游戏内破坏方块的删除物理设备操作。

## 失败判定

- WebUI 为 `signal_emitter`、`signal_receiver` 或 `action_relay` 提供了删除 / 解绑真实方块设备按钮。
- 任意 WebUI 操作触发 `setblock`、破坏真实方块或删除 block entity。
- `signal_receiver` 出现 Action 列表、任意输出目标或 ActionEngine action 执行能力。
- `action_relay` 行更多菜单、详情页或配置 modal 内缺少 Action 列表入口。
- Action 编辑使用 raw JSON textarea。
- command / signal / message / sound action 任一类型无法按当前底层能力查看或编辑。
- command action 错误阻断 `setblock`、`fill`、`clone`、`place`、`function`、`schedule function`、`execute` 等地图控制 / 玩法命令。
- command action 可以通过 WebAdmin 保存服务器管理高风险命令，例如 `ban`、`kick`、`op`、`deop`、`stop` 或 `whitelist`。
- signal action channel 只能纯文本输入，没有暗色 combobox 或手动输入能力被破坏。
- 保存时绕过权限、CSRF、same-origin、edit lock、expectedFingerprint、WebAdminWriteResult 或 audit。
- 多用户修改同一 action_relay 时静默覆盖未保存输入。
- realtime 使用整页 reload、闪屏、关闭无关 modal、重置筛选 / 分页 / 滚动。
- 无关 route 因 action list 修改而频繁重拉大数据。
- 本轮代码进入 matcher、itemSubmit、ConditionEngine、GameController 或 phone/task/blocking/password 联动。

## Console / Network 检查

- Action 列表读取应请求 `GET /api/webadmin/action-relay-actions/{deviceId}`。
- Action 列表保存应请求 `PATCH /api/webadmin/action-relay-actions/{deviceId}`。
- 保存请求应携带 `X-TZZ-WebAdmin-CSRF`，并包含 `expectedFingerprint` / edit lock 相关字段。
- 物理设备基础配置保存应继续使用现有 WebAdmin 写接口和 CSRF。
- realtime 应出现 action relay action/config/device/audit 相关事件。
- Browser console 不应出现未捕获异常。
