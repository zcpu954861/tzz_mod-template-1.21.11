# 测试_8.8_WebAdmin条件模拟诊断回放验收

## 目标

验证 8.8 Condition Runtime Debugger / Doctor / Simulation 是否能解释 8.6 / 8.7 已接入 gate 的判断结果，并保持 replay 只读、无副作用。

本阶段不要求 Codex 启动 Minecraft、不跑 MCP scenario、不生成截图矩阵。真实浏览器验收由用户执行。

## 前置条件

- 当前分支：`feature/condition-runtime-debugger-doctor-simulation`。
- 当前稳定基线：`v1.53.0-condition-runtime-receiver-region-gates`。
- WebAdmin 可访问：`http://127.0.0.1:18080/`。
- 可使用 VIEWER 以上账号查看页面；如需准备条件组配置，使用 EDITOR 或 OWNER。
- `logs/` 不处理、不删除、不提交。

## 精确验证命令

在仓库根目录执行：


本验收不要求游戏内命令创建数据。若需要在游戏内构造 SignalListener、ActionRelay 或 RegionController 触发，请使用 Minecraft TAB 补全确认当前注册子命令；禁止把裸父命令 `/tzz signal`、`/tzz regionctl` 当作测试命令。

## 数据准备

准备至少三个 Condition Group：

- `always_true`：根节点为 `always_true`。
- `always_false`：根节点为 `always_false`。
- 一个不兼容组，例如包含 `container_slot_item_matches` 且绑定到非 container target，或包含 `context_player` 玩家状态变量且绑定到 SignalListener / ActionRelay。

准备至少一个已接入 gate 的目标：

- VBD native trigger 中任一 gate。
- SignalListener gate。
- ActionRelay gate。
- RegionController enter / exit / stay gate。

要求：

- 未配置 conditionGroupId 的目标用于旧逻辑对照。
- 配置 `always_true` 的目标用于 allowed history。
- 配置 `always_false` 的目标用于 blocked history。
- 配置 missing / disabled / invalid / incompatible 的目标用于 Doctor 检查。

## 浏览器验收步骤

1. 登录 WebAdmin，打开 `#/condition-debugger`。
2. 初始无数据时应显示中文空状态：暂无 runtime gate 历史。
3. 触发配置了 `always_true` 的 gate，刷新或等待 silent refresh。
4. 条件调试器列表应新增一条 `通过` 记录。
5. 触发配置了 `always_false` 的 gate。
6. 列表应新增一条 `阻断` 记录，并显示中文 failureReason。
7. 点击记录整行或“详情”，应进入独立完整宽度详情页，URL 形如 `#/condition-debugger/{historyId}`；兼容旧 `#/condition-debugger?id={historyId}` 直接打开也应显示详情页。
8. 详情页应分区显示 targetType、targetId、condition group、failureReason / result summary、context summary、debug tree、Replay 区域和默认折叠的只读技术信息，不能挤在右侧窄栏。
9. 点击 condition group 跳转，应进入 `#/condition-groups/{id}`。
10. 点击“返回列表”，应尽量保留筛选、分页和滚动位置。
11. 点击“模拟重放”，应在详情页内返回 replay result，并显示：
   - 只读：是。
   - 无副作用：是。
   - 不读取 live world：是。
   - 原结果。
   - Replay 结果。
   - 是否一致。
12. 直接打开不存在或已被 ring buffer 淘汰的 `#/condition-debugger/{historyId}`，应显示中文 not found，不白屏。
13. 点击 disabled 的“真实重放 Action”，不应发送真实 action 请求。

失败判定：

- 条件调试器主页面出现 raw JSON editor。
- Replay 会发 signal、执行 action、消费或移动物品。
- 详情页只显示大段 JSON，没有结构化 debug tree。
- 详情页仍挤在 300px 右侧窄栏，或列表页仍承担完整 debug tree / context / replay 展示。
- 点击详情或 replay 导致整页 reload、筛选清空或滚动跳顶。

## 筛选验收

在 `#/condition-debugger` 检查：

- targetType 筛选。
- result 筛选。
- conditionGroupId 筛选。
- targetId 搜索。
- channel 筛选。

失败判定：

- 筛选后页面跳转到其它路由。
- silent refresh 后筛选条件丢失。
- 无匹配结果时没有中文空状态。

## Doctor 验收

打开 `#/doctor`：

应能看到 condition runtime diagnostics：

- missing condition group：ERROR。
- disabled condition group：WARNING。
- invalid condition group：ERROR。
- incompatible binding：ERROR。
- context_player 用在无 player target：ERROR。
- container condition 用在非 container target：ERROR。
- item / inventory condition 用在 unsupported target：ERROR。
- signal history condition 用在 unsupported target：ERROR。
- always_false：WARNING。

失败判定：

- Doctor 自动修改配置或清空 conditionGroupId。
- Doctor 把未配置 conditionGroupId 当错误。
- Doctor 把 SignalReceiver gate 或单条 Action gate 当作当前缺失错误。
- 标题、说明或建议不是中文可读。

## 现有页面最近 gate 状态

检查以下页面：

- VBD 详情 / native trigger config。
- SignalListener detail。
- ActionRelay detail。
- RegionController detail。

应显示：

- 最近一次条件判断：通过 / 阻断 / 错误 / 暂无记录。
- failureReason 或 debugSummary。
- 查看 debug detail。
- 跳转条件组。

失败判定：

- 没有 history 时页面崩溃。
- history API 失败导致主详情页不可用。
- 最近状态卡挤压表格、按钮或输入框。

## Disabled / unavailable 边界

确认：

- 不存在 SignalReceiver gate 配置入口。
- 不存在单条 Action condition gate 配置入口。
- 不存在 GameController / MissionSystem / PhaseController 页面或 API。
- 不存在 raw JSON editor。
- “真实重放 Action”保持 disabled / unavailable。
- Replay 不打开真实编辑表单，不发送 action execution API。

失败判定：

- 出现可点击真实 replay action。
- replay 网络请求引发 SignalBridge emit 或 ActionEngine 执行。
- UI 暗示 8.8 已支持 SignalReceiver gate 或单条 Action gate。

## 响应式检查

检查以下 viewport：

- 1920 x 1080。
- 1536 x 864。
- 1366 x 768。
- 1280 x 720。
- 1024 x 768。

重点：

- history 表格容器可横向滚动。
- right rail 小屏下移或保持可读。
- 筛选栏可换行。
- 分页始终在表格下方。
- debug tree 不撑破页面。
- replay result warning 不覆盖按钮。

失败判定：

- 卡片重叠。
- 表格压住分页。
- right rail 越界。
- 按钮压输入框。
- 文字溢出到相邻卡片。

## Console / Network 检查

打开 DevTools：

- Console 无未捕获异常。
- `GET /api/webadmin/condition-gates/history` 返回 200。
- `GET /api/webadmin/condition-gates/history/{id}` 返回 200。
- `POST /api/webadmin/condition-gates/history/{id}/replay` 返回 200 或中文 safe failure。
- replay response 包含 `readOnly=true`、`noSideEffects=true`、`noLiveWorldRead=true`。
- SSE 收到 `condition_gate_history_appended` 后只做 silent refresh。

失败判定：

- replay 触发写 API、action API 或 signal emit API。
- condition history event 导致整页 reload。
- 401 之外的 API 错误没有中文提示。

## 通过标准

- Runtime history 可以解释 allowed / blocked / error / missing group。
- Debug detail 通过 `#/condition-debugger/{historyId}` 独立完整宽度页面展示结构化 context summary 和 debug tree。
- Replay 只读、无副作用、不读取 live world/service。
- changed / deleted condition group 有中文提示或 safe failure。
- Doctor 覆盖 8.6 / 8.7 已接入 gate binding。
- VBD / SignalListener / ActionRelay / Region 页面展示最近 gate 状态。
- 没有 SignalReceiver gate、单条 Action gate、GameController / MissionSystem / PhaseController。
- 没有改写 8.6 / 8.7 gate 决策语义。
- 验证命令全部通过。
