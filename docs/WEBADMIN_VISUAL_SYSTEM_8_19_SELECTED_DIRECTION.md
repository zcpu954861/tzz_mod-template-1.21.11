## 8.20 Implementation Principles

- Keep the existing page structure.
- Keep existing business logic.
- Keep existing routes, APIs, and runtime behavior.
- Allow component-level visual refactoring.
- Support dark and light theme switching.
- Treat 8.20 as a unified token, component hierarchy, status style, icon semantics, and theme-system implementation, not a simple recolor.

## 8.20 Prohibitions

- Do not change page information architecture.
- Do not change save, delete, rollback, apply, or edit-lock business flows.
- Do not change the core interactions of Logic Chain, Snapshot, Template, or Help.
- Do not change backend APIs or runtime behavior.
