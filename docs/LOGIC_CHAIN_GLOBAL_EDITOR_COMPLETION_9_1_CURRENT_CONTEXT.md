# 9.1 Logic Chain / Global Editor Capability Completion Current Context

9.1 completes controlled editor coverage for existing Logic Chain / Global Editor resources. It extends the current Viewer canvas and typed WebAdmin write paths; it does not introduce a Game Program AST, freeform graph document save, Scratch editor, if / else runtime or new runtime semantics.

## Scope

9.1 is a resource-graph and controlled-config stage:

- Resource graph: Logic Chain still visualizes existing SignalBridge, ActionEngine, Timer, Join, StateVariable and ConditionGroup relationships.
- Controlled config editor: users edit real typed resources through the existing canvas, modals and service APIs.
- Program AST: deferred. GameController, MissionSystem, PhaseController, if / else runtime and full visual programming remain out of scope.

## Implemented Capability

- StateVariable definition can be created and edited through WebAdmin with GLOBAL / PLAYER scope and BOOLEAN / INTEGER / STRING type.
- StateVariable writes use WebAdmin permission, CSRF / same-origin, edit lock, expectedFingerprint, backend validation, audit, realtime and write-before snapshot protection.
- StateVariable graph/reference nodes and state_variable actions link users to the definition page instead of treating the variable as an anonymous value. StateVariable action-first visual semantics keep the action card visually action-like while using StateVariable target/effect accent color for the target.
- ConditionGroup references remain first-class gate references: compatible groups can be selected or cleared from conditionGroupId fields, and the existing ConditionGroup editor route remains the authoring entry.
- Gate nodes and fields are documented and marked as guard references. They express allow / block / skip, not branches, else paths or fallback actions.
- Logic Chain canvas can create a virtual SignalListener pure config node from legal channel connections. It persists technical name, enabled, channel, cooldownTicks and conditionGroupId; display label / note remain draft or audit-only metadata until SignalListenerData has a real metadata field.
- Existing ActionConfig same-index edit now covers SignalListener actions, Timer action buckets, ActionRelay actions and RegionController enter / exit / stay buckets.
- ActionRelay summary cards open a controlled maintenance modal with existing action rows, so users can choose an action index and reuse the same Logic Chain action edit modal instead of editing a freeform list from the canvas. ActionRelay loaded exact object handling reads only the already loaded block entity through the existing no-force-load store helper; unloaded chunks remain summary/read-only with a deferred reason.
- RegionController signal action alias cards carry owner id, trigger bucket and action index metadata, so their same-index edit and reconnect paths are reachable from the graph. Region owner -> action -> downstream channel graph semantics are explicit: the owner RegionController appears upstream, then the owned action alias, then the emitted channel. This is not a freeform graph save and not an independent middle system column.
- RegionController edit hides the old misleading primary "signal channel" field. Signal output channels belong to enter / exit / stay signal actions and are edited through the action list.
- Visible nodes now have an explicit detail result: editable nodes open typed maintenance, StateVariable resource/action nodes jump to the StateVariable page when resolvable, reference cards can locate the primary node, and world-backed nodes show readonly/deferred detail instead of silently doing nothing.
- Action maintenance supports same-index replace / disable, draft-only action delete, and same-bucket action reorder for SignalListener, Timer buckets, ActionRelay and RegionController enter / exit / stay buckets. Delete / reorder payloads preserve owner, bucket, index, typed lock and expectedFingerprint; canceling Logic Chain edit leaves the original action list unchanged.
- Channel endpoint / metadata behavior stays reference based. A channel endpoint is metadata / graph reference, not a runtime consumer.
- The Logic Chain "new node" list uses the 9.1 naming boundary: Channel Endpoint, Signal Join, Timer, Virtual SignalListener, World Device Reference, RegionController and VBD Virtual Block Device. Standalone ActionRelay is removed from the add-node list and is covered by World Device Reference. Pure-config nodes are enabled in the canvas. World Device Reference, RegionController and VBD entries are selectable and start a client-assisted protected draft flow with a required online-player picker / WebAdmin session requirement; backend validation still requires a protected draft id and rejects hand-written fake world / position nodes.
- V8 client-assisted creation keeps the add-node modal open while the game-side flow is running. It uses distinct session purposes for VBD selection, world-device hotbar placement and RegionController corner selection. The WebAdmin graph card is created only after the protected draft reaches selected / placed / completed and the user confirms in the modal; cancelled / failed / expired / not_found sessions do not create a draft card.
- World Device Reference uses a protected three-slot hotbar placement mode for SignalEmitter / SignalReceiver / ActionRelay and restores the player's inventory when the session ends. If the WebAdmin user cancels after game-side placement but before creating the graph card, the backend cancels the protected draft and rolls back the placed block / SignalDeviceStore entry. RegionController uses a RegionPlanner-like corner flow: right-click points in one dimension, then return to the first point after at least three points to complete.
- V10 tightens the client-assisted draft UX: world-device placement suppresses the vanilla nine-slot hotbar and shows the protected three-slot device strip as the only visible chooser; ESC confirmation survives key release so the second ESC cancels the session; RegionController selection reuses the shared RegionPlanner particle / line renderer instead of drawing WebUI geometry; protected world-device drafts also block ordinary signal-device command mutation until WebAdmin saves or cancels them.
- Draft-created Virtual SignalListener, ActionRelay world-device references and RegionController nodes can carry draft Action lists before save. RegionController uses enter / exit / stay buckets; draft signal actions contribute channel references to channel metadata save payloads and graph placement. World-device draft cards show the user-entered / protected-draft device type, id, position and downstream output information instead of collapsing to a generic label.
- Layout repair now treats producer/source drafts and saved producers as target-channel anchored. RegionController owner cards follow their enter / exit / stay action group toward the downstream channel, and adjusted same-column cards are center-balanced to avoid large vertical gaps and long flying edges. Object display names remain owned by the object and are not replaced by downstream channel display names.
- Placed new-node draft edit modals now treat Cancel as a real discard. Input handlers may update the in-memory preview while the modal is open, but `data-logic-chain-placed-draft-cancel-discards` restores the pre-modal snapshot unless the user clicks Update Draft. Opening the add-node modal without changing fields no longer makes the editor dirty.
- Protected draft object registry tracks Logic Chain client-assisted sessions by draftSessionId, editLockId, actor, bound player, object type, world / position, previous block state, state and allowed operations. Selection completion can record draft-only VBD / world-device / region / itemSubmit / container capture entries, and cancel / timeout / server stop marks them terminal instead of committing typed config. Recoverable commit failures mark the draft with `lastCommitFailure` and return it to configuring state for retry. Protected mutation checks require the original WebAdmin actor as well as the matching lock / draft session.
- VBD nodes open an actual Logic Chain node editor instead of a whole-node deferred message. Existing VBD nodes expose safe identity/detail fields and route itemSubmit / container editing to the mature VBD editors; new VBD protected drafts can accumulate itemSubmit / container requirement drafts before save.
- VBD Logic Chain drafts require protected selection and one downstream `vbd_outputs_channel` edge; the saved VBD channel is derived from the graph connection instead of prefilled during selection. Browser/game-side VBD capture UX still needs manual verification. itemSubmit / container payloads are validated and committed into the VBD draft save path; consumeCount/count mismatches fail validation instead of being accepted and silently dropped. VBD delete uses the VBD lifecycle delete path and unbinds the virtual device state without removing the original block.
- Existing typed-owned node delete is represented as `nodeDeletes` and is limited to known stores such as Signal Join, Timer, SignalListener, VBD unbind, and physical SignalEmitter / SignalReceiver / ActionRelay device deletion. Reference nodes or nodes without provable owner/store are rejected with a Chinese validation error.
- Existing saved world device editing in Logic Chain now treats graph edges as the owner of channel relations. SignalEmitter / VBD no longer expose editable output-channel fields in the node panel, and SignalReceiver / ActionRelay no longer expose editable input-channel fields; the panel shows a readonly graph-owned connection summary and hidden typed value only for draft save.
- SignalReceiver and ActionRelay are graph consumers, not trigger sources. They render on the channel consumer side with `channel -> SignalReceiver` / `channel -> ActionRelay` semantics, non-source styling and consumer/sink/executor markers for saved and draft world-device references.
- Existing VBD cards open an in-place trigger-card editor. Trigger cards lead to second-level trigger-specific pages with modal-local page stack and per VBD node / trigger / page scroll memory; toggling native trigger enabled state, editing fields, or changing requirement rows rerenders back into the same modal context instead of jumping to the top or closing the editor. Native trigger enabled / disabled state, channel, cooldown / interval and compatible condition group fields are edited as Logic Chain draft under a dedicated VBD native-trigger typed lock. itemSubmit requirements live under the right-click trigger page and container requirements live under the container-change trigger page. Their game-assisted capture/edit entries reuse the standalone VBD template sessions in `logicChainDraftOnly` mode, return captured requirements to the current Logic Chain draft, and write the formal VBD only when the Logic Chain save is confirmed. The editor no longer navigates to the standalone VBD page and does not drop the Logic Chain draft.
- VBD native trigger draft summaries are rendered as Chinese readable rows instead of primary raw `nativeTriggerJson`. Redstone / BlockState / right-click / itemSubmit / container open / close / change changes show enabled state, mode, output channel, cooldown / interval and condition group fields in the unsaved-diff banner.
- VBD native trigger output-channel draft changes now update the edit-mode Logic Chain graph before final save. Enabled trigger outputs create draft VBD -> Channel edges, remove superseded old trigger-output edges, and reuse the existing target-channel-adjacent placement so the VBD card follows the new target channel. New channel ids are represented as draft channel endpoint cards without persisting a fake graph document.
- Logic Chain itemSubmit / container capture terminal states show captured / applied status and return-to-trigger controls. After a successful draft-only capture the primary button no longer remains "打开 GUI"; 主按钮显示返回/已加入草稿, "重新捕获" is only a secondary action, and the captured requirements remain in the current Logic Chain draft until final save.
- VBD trigger draft graph repair now treats `(VBD, triggerKey)` as the stable identity for trigger output preview. Editing an existing trigger updates the same VBD trigger representation from the clicked source card, removes stale main / focus / old-channel `vbd_outputs_channel` edges, and connects only to the selected trigger's configured target channel. itemSubmit / container draft-only saved realtime events are handled as draft writeback events, so the captured requirements are merged into the current Logic Chain VBD trigger draft before the modal returns, including an explicit empty requirement list when the game GUI was saved empty. Cancelled / failed capture sessions keep the modal and expose a restart button; retry is not disabled by frontend precheck reasons, has modal-local click plus pointerup handling, and clears stale session / lock state before opening a fresh game GUI. The backend still revalidates Logic Chain lock, target player and VBD trigger context before starting the new session.
- SignalEmitter remains a producer and derives its output channel from `world_device_outputs_channel`; SignalReceiver and ActionRelay are consumers and derive their input channel from `channel -> device` `world_device_consumes_channel`. Missing consumer input now reports `logic_chain_world_device_input_channel_required` instead of the producer output error.
- Connection mode is cleared after a successful candidate / channel endpoint connection and a normal graph card click exits connection mode before selecting the card, so adding a new card no longer blocks viewing or editing other cards.
- Node delete now requires dry-run impact acceptance plus the exact fixed phrase `我确认删除该节点`. VBD delete unbinds virtual device state without breaking the world block; physical SignalEmitter / SignalReceiver / ActionRelay delete removes the world device block after explicit warning. A save is fail-closed to one node delete at a time until transactional multi-delete exists.
- Existing Action delete / disable / up / down controls are available at the existing-node maintenance action-list level, and selecting an action card in the graph exposes right-panel delete as a draft action delete. The single Action edit modal only edits content fields such as type, payload, enabled, cooldown and conditionGroupId.
- Action maintenance uses one Action Panel entry and a second-level panel for RegionController enter / exit / stay, ActionRelay, SignalListener and Timer buckets. Signal action channel fields use existing-channel combobox selection while still allowing a new channel name. Draft owner action cards now render immediately in the graph for signal and non-signal actions; ActionRelay draft actions render after the `channel -> ActionRelay` upstream connection exists, not from producer-side slot placement. Signal actions are placed between owner and target channel when the target channel is known, while state/timer/command/message/sound actions appear as owner downstream action cards.
- Node and action deletes remain draft-only until save. Pending-delete node/card/action visuals are grey/desaturated, show a pending-delete badge and can be undone or recovered by canceling the Logic Chain edit session. The unsaved-diff banner includes nested draft-created actions and pending-delete action rows, and fails soft if a summary cannot render.
- World Device Reference protected placement now normalizes the selected slot to the three protected hotbar slots on entry, wheel and number-key changes sync the selected slot to the server, and the HUD shows the selected device rather than the aimed block.
- A Logic Chain edit session can contain multiple draft operations. Save validates all node creates, existing edits, action deletes, action reorders, node deletes, connections and VBD/world/region protected drafts together. Non-conflicting cross-target action operations can save together; multiple independent writes against the same action owner/bucket are rejected with `logic_chain_action_target_multi_write_conflict` until a true same-list batch patch API exists.
- Target typed locks are checked before creating target-edit drafts and are prevalidated again before save with `logic_chain_target_lock_preflight_validation`, so the UI can distinguish the main Logic Chain lock from missing target locks before the final typed write.

## Preserved Interactions

- Editing stays inside the existing Logic Chain Viewer canvas.
- The main editor lock, typed target locks, dirty confirm and custom top-center toast remain required.
- Draft slot placement, green plus connection mode, draft edge highlight, direct connection to existing channel cards, focus channel selector and whole-chain list entries remain the accepted 8.14 / 8.16 behavior.
- Save writes typed config services only. The canvas never persists a fake graph document.
- Save failure keeps draft state and lock information when recoverable.
- Save remains typed-service based and prevalidated. VBD protected draft commit, including itemSubmit / container requirement drafts, is wired through the VBD store path. World Device Reference and RegionController protected drafts now use explicit typed commit / rollback adapters: world-device save checks the loaded block, block entity and SignalDeviceStore identity before committing, while RegionController save creates Region + Controller and rolls both back on failure. Fake world / position payloads remain rejected.

## Security And Write Rules

All new or expanded writes continue to use:

- permission and role policy;
- CSRF and same-origin checks;
- edit lock and heartbeat / release;
- expectedFingerprint conflict checks;
- backend validation as the authority;
- WebAdminWriteResult response shape;
- audit and realtime events;
- write-before auto snapshot and operationDiff where the route is covered.

## Explicit Non-goals

9.1 does not add:

- GameController, MissionSystem or PhaseController;
- Game Program AST, full Logic Chain Editor or Scratch editor;
- if / else runtime, branch node, fallback action or else path;
- freeform graph document save;
- new ActionType or new ConditionNodeType;
- typed actions / Rich Text Builder;
- freeform world mutation, setblock / clone / structure placement or automatic world entity copy outside the protected client-assisted world-device placement flow;
- old node arbitrary move / reorder and reference-node delete;
- old action arbitrary cross-bucket move;
- StateVariable GAME / TEAM / GAME_PLAYER scope or scoreboard migration runtime;
- old datapack task implementation.

## Deferred

- Template apply still does not create ConditionGroup definitions or StateVariable definitions from template packages.
- ConditionGroup inline create-and-bind from every gate picker can be improved later; 9.1 keeps the existing ConditionGroup editor as the creation route and binds compatible existing groups from gate fields.
- World device hotbar placement and RegionController corner selection now have server/client protected-session wiring and real typed commit / rollback adapters, but still require manual game-side verification in a real Minecraft client. The manual pass should cover vanilla-hotbar suppression, three-slot hotbar wheel / number selection, extreme-height HUD safe area, ESC / WebUI cancel cleanup and restart, draft block / command protection, RegionPlanner-like point / line preview, draft action panels and saved/draft target-channel-adjacent center-balanced layout. Fake world-backed draft save remains rejected.
- Logic Chain VBD itemSubmit / container capture UX still needs manual browser/game verification, but the WebAdmin path now keeps the capture inside the Logic Chain modal, preserves trigger-page scroll/history, and routes captured item/container templates into draft-only payloads that are validated and wired into the VBD commit path instead of being silently dropped.
- Existing action delete/reorder and typed-owned node delete are now Logic Chain draft operations. Old arbitrary move, cross-bucket reorder and reference-node delete remain rejected.
- Component export and placeholder binding apply remain deferred.
